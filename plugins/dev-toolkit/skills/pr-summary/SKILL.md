---
name: pr-summary
description: Summarize a pull request or code diff into a clear description. Use when the user asks for a PR description, to summarize a diff, or to explain what a branch changes.
---

When summarizing a pull request or diff:

1. Read the diff to understand the full change set.
2. Open with a one-sentence summary of what the PR does and why.
3. List the key changes as bullets, grouped by area if there are many.
4. Call out anything a reviewer should pay special attention to — risk, data migrations, breaking changes, follow-ups.

Be concise. Favor what the reviewer needs to know over an exhaustive file-by-file list.
